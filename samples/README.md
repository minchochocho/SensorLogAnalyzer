# 센서 모의 데이터

두 CSV는 프로그램 개발용으로 작성한 모의 기록이며 실제 센서 측정값이 아닙니다. CSV 파서와 검증 기능은 아직 구현 전입니다. 아래 결과는 구현 후 확인할 기대값입니다.

## 파일 형식

- UTF-8 (BOM 없음), 쉼표 구분, 첫 줄은 헤더
- 열 순서: `timestamp,distance_cm,light_adc`
- 시간 형식: `YYYY-MM-DD HH:MM:SS`, 유효한 날짜와 24시간제 시각
- 거리: 유한한 숫자, 단위 cm, 이번 샘플의 유효 범위 `0 < 거리 <= 400`
- 조도: 정수 ADC 원시값 `0~255` (lux 아님)
- 필수값 누락, 열 수가 3개가 아닌 행, 형식 및 범위 위반은 오류 행
- 정상 파일은 1초 간격 20개 기록

초기 파서는 이 단순 형식부터 지원할 예정입니다. 따옴표 안의 쉼표나 여러 줄 필드 등 일반 CSV 전체 문법 지원을 의미하지 않습니다.

## sensor_normal.csv

기대 결과: 데이터 **20행, 정상 20행, 오류 0행**. 헤더는 행 수에서 제외합니다.

거리 경고는 데이터 오류와 다릅니다. 위험 거리여도 형식과 범위가 유효하면 정상 데이터입니다.

초기 판정 기준안:

- 거리 `<= 30`: 위험
- 거리 `> 30`이고 `<= 60`: 주의
- 거리 `> 60`: 안전
- ADC `>= 180`: 어두움, 그 미만: 밝음 (이 프로젝트의 센서 해석 기준)

위 기준 적용 시 거리 상태는 안전 10행, 주의 5행, 위험 5행입니다. 밝기 상태는 밝음 11행, 어두움 9행입니다. 거리와 밝기는 독립적으로 판정합니다.

30cm·60cm·ADC 180의 경계 및 주변값과 ADC 양 끝값 0·255를 포함합니다.

## sensor_errors.csv

기대 결과: 데이터 **20행, 정상 8행, 오류 12행**. 오류 행 이후의 정상 행도 계속 처리해야 합니다.

아래 번호는 헤더를 제외한 데이터 행 번호입니다. 실제 파일 줄 번호는 각각 1을 더합니다.

- 2행: 거리 누락
- 3행: 거리에 숫자가 아닌 `abc`
- 4행: 거리 `-1` (측정 실패값)
- 5행: 거리 `0` (이번 샘플의 유효 범위 밖)
- 6행: ADC `256` (상한 초과)
- 7행: ADC `-1` (하한 미만)
- 8행: ADC에 숫자가 아닌 `abc`
- 9행: ADC 누락
- 10행: 시각의 시간이 `25` (유효하지 않은 시간)
- 11행: 시각 누락
- 12행: 열 부족 (2개)
- 13행: 열 초과 (4개)

정상 행은 1행과 14~20행입니다. 오류를 숫자 0으로 치환하거나 앞 행의 값으로 채우지 않고 원래 행 번호와 오류 원인을 보존하는 것을 목표로 합니다.

## 확인 순서

1. 현재 단계: CSV 열기 버튼으로 파일을 선택하고 경로 표시 확인
2. 파서 구현 후: 정상 파일에서 20개 데이터 행 표시 확인
3. 검증 구현 후: 오류 파일에서 정상 8행·오류 12행 구분 확인
4. 판정 구현 후: 정상 파일의 경계값 및 상태별 행 수 확인

현재 앱에서 경로만 표시되고 목록이 비어 있는 것은 예상된 상태입니다.
